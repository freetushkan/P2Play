# Веб-интерфейс P2Play: библиотека и паритет TorrServer

## Цель и границы

Служебного экрана MediaMesh недостаточно для автономного медиаплеера. В `/ui/`
нужно управлять собственной библиотекой без внешнего pPlay/Silo. Общий устаревший
план из `old_docs/P2Play_MediaMesh.md` не ограничивает этот объём.

Одна копия HTML/JS/CSS остаётся общей с Silo-плагином. Управление библиотекой
P2Play доступно только в core-host; в Silo библиотекой управляет сам Silo.
Нельзя направлять запросы к библиотеке P2Play из Silo-host или выдавать библиотеку
служебного daemon token за библиотеку вошедшего пользователя Silo.

## Ближайшая реализация

- [ ] Отдельная вкладка Library: библиотека текущего пользователя, обновление,
      пустое состояние и явные ошибки.
- [ ] Добавление magnet / поддерживаемой ссылки и бинарного `.torrent` через
      существующий POST `/api/torrents` (JSON / multipart `file`), название и
      произвольная категория. Сохранение в библиотеку включено явно.
- [ ] Поиск в библиотеке по словам названия/хэша/категории, без учёта регистра
      (включая ё/е); категории «все», «без категории» и реальные значения.
- [ ] Детерминированная сортировка библиотеки: дата, название, размер в обе стороны.
      Фильтрация и сортировка охватывают весь ответ библиотеки, не первые 50 записей.
- [ ] Изменение категории через PUT `/api/torrents/:hash/meta` и удаление через
      DELETE `/api/torrents/:hash` с подтверждением. Удаление означает исключение
      из библиотеки пользователя, не обещание удаления данных других пользователей.
- [ ] Browser acceptance: login, magnet, multipart, фильтры/сортировка, категория,
      отмена/подтверждение удаления, ошибки, сохранение после restart и изоляция
      пользователей. Проверять также, что Silo-host не показывает core-only UI.

## Контракты и безопасность

Использовать текущий authenticated API, cookie login и same-origin fetch, без
хранения токена в JS/localStorage и без токенов в URL. FormData передавать без
ручного Content-Type (boundary формирует браузер). Недоверенные строки выводить
через textContent. Не отображать внешние постеры/HTML и не ослаблять CSP.
Ошибка не должна очищать форму добавления; повторный submit блокируется на время
операции. Пустой файл и одновременно файл+ссылка отклоняются явно.
Метаданные категории сейчас общие для одного infohash на сервере, принадлежность
библиотеке — per-user; UI должен обозначать эту границу, а не обещать per-user meta.

## Следующие шаги до заявления полного паритета

- [ ] Сопоставить остальные сценарии MatriX/Silo: файлы/папки, stream/player,
      viewed/reset/progress, сведения/peers/cache, настройки и управление users.
- [ ] Полный поиск MediaMesh с выбором каталогов/тегов, server-side сортировкой и
      пагинацией. Текущий поиск каталога ограничен 50 результатами; нельзя выдавать
      сортировку этой страницы за сортировку всего каталога.
- [ ] Приёмка Android WebView, embedded LAN и целевых устройств; Linux browser CI
      не заменяет эту проверку.

Публичные compatibility API и wire-format MediaMesh этим шагом не меняются.
