# Переработка web-ui P2Play

## Цели и ориентиры

Интерфейс следует паттерну legacy backend MatriX/Silo в главном: постоянная
навигация сведена к библиотеке и поиску, основное место экрана занимает
содержимое, редкие административные действия находятся за настройками.
P2Play сохраняет собственные операции MediaMesh и управления торрентами, но не
переносит в главное окно отдельные крупные панели добавления, импорта и
диагностики.

## Основной сценарий

- После входа native-host открывает библиотеку. Это единственный стартовый
  рабочий экран, карточки показывают сохранённый постер/обложку, состояние,
  категорию и быстрые действия.
- Добавление запускается верхней кнопкой и отображается в компактном modal.
  Файл торрента или magnet/link выбирается в форме; постер опционален (URL или
  файл), title/category можно отредактировать.
- Поиск каталога доступен из того же modal. Результат выбирается, значения
  подставляются в родительскую форму, modal не закрывается. Back/Cancel
  возвращают к форме без сброса введённых значений. Отдельная Discover-вкладка
  оставлена как самостоятельный путь поиска и основной точкой входа Silo-плагина.
- Lists, Continue Watching, Server, Users и Silo Connection размещены внутри
  одного окна Settings. Библиотека и поиск остаются отдельными представлениями.
- Настройки темы и языка находятся в шапке; повторные элементы в окне Settings
  убраны. Первый раздел настроек называется «Основные» и содержит общие
  действия с данными библиотеки.

## Визуальная система

Светлая тема — основной нейтральный вариант; тёмная переопределяет общие CSS
custom properties, поэтому карточки, формы, состояния, модальные окна и списки
не имеют отдельного дублированного набора стилей. Адаптивная сетка сохраняет
плотность библиотечных карточек на узких экранах, а диалоги превращаются в
полноширинные нижние панели на телефонах. Основные кнопки действий и аккаунт
используют векторные SVG-иконки.

Уведомления в нижнем правом углу появляются только для обратной связи о
действии/ошибке и автоматически скрываются. Простая загрузка или переключение
раздела не создаёт toast, а ошибка остаётся видимой дольше обычного сообщения.

## Локализация и пользовательские настройки

Словари лежат отдельно в `plugins/mediamesh/lang/en.json` и
`plugins/mediamesh/lang/ru.json`. Они встраиваются в core UI вместе с HTML,
JS и CSS и публикуются Silo-плагином как статические ресурсы. UI-тест сверяет
ключи, используемые представлением списков, включая пустые состояния.

В native-host `GET/PUT /api/v1/preferences` сохраняет `language` (`en`/`ru`)
и `theme` (`light`/`dark`) в записи пользователя `auth.json`. В Silo-host
предпочтения сохраняются в браузере с ключом, включающим Silo user ID: плагин
не должен писать настройки в приватное хранилище самого Silo.

Счётчики файлов форматируются как «Files: 4» (локализуемая подпись и число в
конце), а не как изменяемое по языкам сочетание числа с формой существительного.

## Постеры и совместимость

Постер, добавленный в форме, хранится в `covers/` на узле P2Play. JSON торрента
продолжает отдавать строковое поле `poster`, теперь это same-origin путь
`/api/v1/torrents/{hash}/poster`. Существующие клиенты не требуют нового
формата JSON. Подробности, лимиты, URL security и lifecycle описаны в
[`covers.md`](covers.md).

## Проверки

`tools/ui-test.py` покрывает native preferences, API постеров и статические
регрессии интерфейса: отсутствие дублирующих селекторов темы/языка, имя
раздела «Основные», автоскрытие toast, локализацию счётчика файлов и списков.
Browser режим (Playwright) должен дополнительно проверять стартовую библиотеку,
переключение языка/темы, добавление через modal, возврат из catalog search в
форму и разделы Settings.

Browser/Playwright тест и приёмку реального Android WebView нужно отличать от
успешной сборки core: CI без браузера не доказывает полноценную визуальную
приёмку на реальных устройствах.
